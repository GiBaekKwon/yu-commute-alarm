## 8장 — 부가 기능: 통학 계획 · 아이폰 알람 · 동기화 (1:20)
**[화면]** 통학 계획 + QR 캡처

아침 통학 부분입니다.
**출발지와 도착지**를 넣으면 **ODsay 길찾기 API**가 대중교통 이동 시간을 계산합니다. 예를 들어 반월당역에서 영남대까지 30분입니다.
여기에 준비 시간과 여유 시간을 더해서, **요일마다 첫 수업 기준으로 출발 시각과 기상 시각**을 거꾸로 계산합니다.
**[강조]** 주소는 저장하지 않습니다. 저장하는 것은 **준비, 이동, 여유 세 가지 '분' 숫자뿐**입니다.

그리고 실제로 깨워 주는 건 결국 폰 알람입니다.
그래서 **아이폰 단축어 연동**을 만들었습니다. PC 화면의 **QR을 아이폰으로 한 번 찍으면, 요일별 기상 알람이 시계 앱에 반복 알람으로** 들어갑니다.
시간표가 바뀌면 다시 찍으면 되고, 예전 알람은 알아서 지웁니다.
**[강조]** 브라우저가 꺼져 있어도 알람은 울립니다.

여기에 전날 밤 ntfy 폰 알림, 로그인 없이 **8자리 동기화 코드**로 PC와 폰이 같은 시간표를 보는 기능도 있습니다.

## 9장 — 시스템 구조 · 네이버클라우드 배포 (1:00)
구조는 단순합니다.
폰이나 PC 브라우저가 **네이버클라우드 서버의 Nginx**에 접속하면 정적 웹 페이지를 받습니다.
에타 변환, 길찾기, 동기화 코드 저장은 **Flask API**가 맡는데, 외부에 열지 않고 **내부 5100번 포트**에서만 돌고 Nginx가 `/wakeup/api/` 경로로 연결해 줍니다.
전날 밤 알림은 **1분마다 도는 예약 작업**이 ntfy로 보내고, 크롬 확장은 같은 API로 시간표를 받아 갑니다.

API 서버는 **systemd로 자동 재시작**되고, 배포할 때마다 이전 버전을 **날짜별로 백업**합니다.
길찾기 API 키는 화면이나 코드에 없고, 서버 안의 비밀 파일에서만 읽습니다.
화면은 외부 라이브러리나 CDN 없이 **순수 HTML·CSS·JS**입니다.
**[강조]** 지금도 공인 IP로 외부에서 접속됩니다. 시연에서 직접 보여 드리겠습니다.

## 10장 — 신뢰성 · 보안 (0:50)
설계 원칙은 네 가지입니다.
1. **프라이버시 최우선**: 주소, 이름, 학번 입력칸 자체가 없습니다.
2. **계정 정보 미수집**: 에타 비밀번호와 쿠키를 받지 않고, 공개 링크만 한 번 읽습니다.
3. **서버 보호**: 에타 요청은 IP당 1분 10회, 길찾기는 1분 5회와 하루 300회로 제한합니다. 데이터 폴더 밖에는 쓸 수 없습니다.
4. **외부 장애 대비**: 등록 후에는 에타 없이 동작합니다. 길찾기가 안 되면 2호선 시각표로 대신 계산하고, 확장은 오프라인에서도 마지막 데이터를 씁니다.

## 11장 — Agentic AI 개발 방법 (1:30)
이 프로젝트는 처음부터 끝까지 **Claude Code 에이전트**와 함께 만들었습니다. 그냥 시키기만 한 게 아니라 **에이전트를 통제하는 장치**를 네 가지 썼습니다.

1. **Plan 모드와 CLAUDE.md**: 먼저 Plan 모드로 `plan.md` 설계를 만들고, CLAUDE.md에 **반드시 지킬 규칙 7개**를 적었습니다. 개인정보 저장 금지, 추측 금지, 외부 라이브러리 금지 같은 것들입니다. 에이전트가 규칙에 어긋나는 코드를 만들려고 하면 이 규칙이 막습니다.
2. **세션 분리 병렬 개발**: 대시보드 담당 세션과 크롬 확장 담당 세션을 나누고, 서로 상대 폴더를 건드리지 않게 범위를 제한했습니다.
3. **자동 검증**: 10분 경계, 중복 알림, 360px 화면 같은 경계 조건을 테스트로 만들었습니다. 지금 **확장 77개, API 44개를 포함해 480개가 넘는 테스트가 전부 통과**합니다.
4. **커스텀 스킬**: `ext-check`라는 스킬을 직접 만들어서, 확장 테스트와 JSON 점검이 통과하면 버전을 올리고 설치 방법까지 안내하게 했습니다.

## 12장 — AI와 함께 해결한 문제 (1:15)
개발 중에 실제로 막혔던 문제들입니다.

- **사례 1, 캐시**: 배포했는데 에타 가져오기가 안 됐습니다. 원인은 브라우저가 예전 JS 파일을 계속 쓴 것이었습니다. 파일 주소에 `?v=` 버전을 붙이는 규칙을 CLAUDE.md에 넣고, 빠뜨리면 테스트가 실패하게 만들었습니다.
- **사례 2, 포트 충돌**: 같은 서버의 기존 메모 앱이 5000번 포트를 쓰고 있었습니다. 통학 API를 5100번으로 분리하고 Nginx 경로로 연결했습니다.
- **사례 3, 일요일 발표**: 발표가 일요일이라 실제 수업이 없어서 10분 전 알림을 보여 줄 수 없었습니다. 그래서 **N분 뒤 수업을 만들어 주는 시연 모드**, `?demo=9`를 만들었습니다.
- (시간 되면) **사례 4, 규칙과 기능의 충돌**: QR 코드를 만들려면 라이브러리가 필요한데, 규칙은 외부 라이브러리 금지였습니다. CDN 대신 서버에 파일 복사본을 두고, CLAUDE.md에 **예외로 기록**했습니다.

**[강조]** 원칙은 하나였습니다. **문제를 찾고, 원인을 밝히고, 규칙과 테스트로 남겨서 다시 생기지 않게** 하는 것입니다.

미리보기에서 과목, 요일, 강의실을 확인하고, 시간 없는 과목은 몇 개 뺐는지도 알려 줍니다.
저장을 누르면 대시보드가 바로 내 시간표로 바뀝니다.
(링크 형식이 틀리면 이렇게 이유를 알려 준다 — 시간 남으면 잘못된 링크 한 번 보여 주기)

### ④ 크롬 확장 (1:00)

**[화면]** 통학 계획 → 출발지 `반월당역` · 도착지 `영남대` → **[이동 시간 계산]** → **[통학 시간 저장]**

저장하면 요일별 출발·기상 시각 표와, 다음 수업 카드 아래 **출발까지 남은 시간**이 나옵니다.
**[화면]** QR 보여 주기 → 아이폰 카메라로 찍기 → 시계 앱 알람 보여 주기
이 QR을 아이폰으로 찍으면, 보시는 것처럼 요일별 기상 알람이 시계 앱에 들어갔습니다.
전날 밤 9시에 오는 ntfy 알림은 이런 모습입니다. **[화면]** 미리 캡처한 ntfy 알림

## 14장 — 한계 · 향후 계획 · Q&A (0:45)
아직 부족한 점도 있습니다.
이동 시간은 시간표 기준이라 **실시간 지연은 반영하지 못하고**, 10분 전 배너는 대시보드를 열어 둬야 동작합니다. 공휴일이나 시험 기간 같은 학사 일정도 아직 반영하지 않습니다.

앞으로는 **실시간 버스 도착 정보**를 연동하고, 웹과 크롬 확장에 나뉘어 있는 **계산 로직을 하나로 합칠** 계획입니다.

정리하면, **에타 링크 한 번, QR 한 번으로 아침 기상부터 다음 수업 10분 전까지** 지켜 주는 서비스입니다.
